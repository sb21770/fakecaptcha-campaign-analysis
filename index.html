Executive Summary

This analysis documents a sophisticated multi-stage fileless malware campaign discovered while attempting to access a payment page on an Israeli volunteer organization website that provides assistance services to people in need.

Upon navigating to the payment page to donate for services, a suspicious CAPTCHA verification popup appeared, masquerading as a Cloudflare security check. The CAPTCHA instructed users to press Win+R, then Ctrl+V, then Enter — a classic social engineering technique to execute a malicious PowerShell command that had been silently copied to the clipboard.

Key Discovery: This campaign operates a modular C2 infrastructure that dynamically serves different final payloads. During analysis, two distinct malware families were observed:

  • Lumma Stealer (cs.bin) — A native C/C++ info stealer targeting browsers, crypto wallets, and messaging apps
  • Cryptocurrency Clipboard Hijacker (clipx64.bin) — A crypto clipper with 17 hardcoded attacker wallets

Reverse engineering using Ghidra revealed the clipboard hijacker contains code to exclude Russian victims by checking for keyboard layout 0x419 (Russian), strongly indicating Russian origin.

Fileless Execution Technique - .NET Compilation

The attack uses PowerShell's Add-Type cmdlet to achieve fileless execution. This technique compiles C# code at runtime, creates a temporary DLL in memory, loads it, then deletes the temporary files — leaving no persistent artifacts on disk.

PowerShell
Add-Type
→
csc.exe
C# Compiler
→
Temp .DLL
Bridge Code
→
Load & Delete
Fileless!
Evidence: Attack Compilation Flow
Process Monitor showing the .NET compilation flow: PowerShell calls Add-Type, which invokes csc.exe (C# compiler) to create temporary DLL files.
Evidence: Temporary DLL Creation in Procmon
Procmon capturing the creation of temporary .cmdline and .dll files in %TEMP%. These files are created, loaded into memory, then immediately deleted.

How It Works

Step Process Action Result
1 PowerShell Add-Type with C# code Triggers .NET compilation
2 csc.exe Compiles C# → .cmdline file Temp source in %TEMP%
3 cvtres.exe Resource compilation Processes resources
4 csc.exe Creates .dll file Bridge DLL with Win32 APIs
5 PowerShell Loads DLL, deletes files Fileless execution

Why This Technique?

PowerShell cannot directly call Windows APIs like VirtualAlloc and CreateThread. The attacker uses Add-Type to compile C# code declaring these APIs, creating a temporary "bridge" DLL. Once loaded into memory, the temporary files are deleted, achieving fileless execution that evades traditional file-based detection.

Cryptocurrency Clipboard Hijacker Analysis

During live execution, the C2 server delivered clipx64.bin — a cryptocurrency clipboard hijacker. This malware monitors the Windows clipboard for cryptocurrency wallet addresses and silently replaces them with attacker-controlled addresses.

How Clipboard Hijacking Steals Money

When a victim copies a cryptocurrency address (e.g., to send payment), the malware:

  1. Detects the wallet address pattern in clipboard
  2. Silently replaces it with the attacker's wallet
  3. Victim pastes the address and sends funds
  4. Money goes to attacker instead of intended recipient

Reverse Engineering Evidence - Ghidra Analysis

The clipboard hijacker binary was decompiled using Ghidra to obtain C-like pseudo-code. This revealed the exact implementation of the Russian keyboard check and clipboard swap mechanism.

Russian Keyboard Check (0x419) - Proof of Origin

The malware checks if the system has a Russian keyboard layout (LCID 0x419) and exits immediately if detected — a common technique used by Russian cybercriminals to avoid infecting Russian systems.

Evidence: Ghidra - Russian Check Code (0x419)
Proof of Russian Origin: Ghidra decompilation showing the exact code that checks for Russian keyboard layout (0x419). If detected, the malware returns 1 (exits), protecting Russian users.
Ghidra Decompiled Code - Russian Check Function
// Function: FUN_1400014bc - Russian Keyboard Check local_18 = GetKeyboardLayout(0); local_1a = (short)local_18; if ((local_1a == 0x419) || (local_1a == 0x419)) { uVar1 = 1; // Russian detected → EXIT } else { // Check all installed keyboard layouts local_20 = GetKeyboardLayoutList(10, local_78); for (local_c = 0; local_c < local_20; local_c = local_c + 1) { local_22 = (short)local_78[local_c]; if ((local_1a == 0x419) || (local_22 == 0x419)) { return 1; // Russian in list → EXIT } } } return uVar1; // Not Russian → Continue attack

What 0x419 Means

0x419 is the Windows Language Code Identifier (LCID) for Russian. This code explicitly excludes Russian-speaking users from being targeted — a hallmark of Eastern European cybercrime operations. The malware authors are protecting their own countrymen.

Clipboard Swap Mechanism - SetClipboardData

Ghidra also revealed the exact function that performs the wallet address replacement:

Evidence: Ghidra - Clipboard Swap Function
The Attack Mechanism: Decompiled function showing OpenClipboard, EmptyClipboard, GlobalAlloc, strcpy (copy attacker's wallet), and SetClipboardData — the complete clipboard hijack.
Ghidra Decompiled Code - Clipboard Swap Function
// Function: FUN_14000177e - Replace Clipboard Content undefined8 FUN_14000177e(char *param_1) { // param_1 = attacker's wallet address BOOL bVar1; HGLOBAL hMem; LPVOID pDest; bVar1 = OpenClipboard((HWND)0x0); // Open clipboard if (bVar1 != 0) { EmptyClipboard(); // Clear current content hMem = GlobalAlloc(0x42, strlen(param_1) + 1); // Allocate memory pDest = GlobalLock(hMem); // Lock memory strcpy(pDest, param_1); // Copy ATTACKER'S wallet address GlobalUnlock(hMem); // Unlock memory SetClipboardData(1, hMem); // 1 = CF_TEXT, set new content CloseClipboard(); // Close clipboard } return 0; }

How the Swap Works

  1. OpenClipboard(0) — Gain access to the clipboard
  2. EmptyClipboard() — Remove the victim's copied address
  3. GlobalAlloc + strcpy — Prepare attacker's wallet address
  4. SetClipboardData(CF_TEXT, ...) — Replace with attacker's wallet
  5. Victim pastes → Sends money to attacker!

Conclusions & Recommendations

Key Findings

  • Active campaign targeting payment pages
  • Uses fake CAPTCHA with Cloudflare branding for social engineering
  • Sophisticated 5-stage fileless attack using Donut shellcode
  • Modular payload system — C2 dynamically serves different malware
  • Two confirmed payloads: Lumma Info Stealer and Crypto Clipboard Hijacker
  • Clipper contains 17 hardcoded attacker wallets for cryptocurrency theft
  • Russian origin confirmed — malware excludes systems with Russian keyboard (0x419)
  • Uses .NET compilation bridge (Add-Type) for fileless API access

Final Assessment

This campaign demonstrates a highly sophisticated, modular malware operation with Russian origins. The attackers have built infrastructure capable of delivering different payloads based on targeting needs — from traditional info stealers to cryptocurrency clippers. The use of fileless techniques, Donut shellcode, and .NET compilation bridges makes detection challenging. The explicit exclusion of Russian victims via keyboard layout checks strongly indicates Eastern European cybercriminal origin.
